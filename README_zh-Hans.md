# ImgSteg（图隐）

[English](README.md) · [在线使用](https://richadowonosas.github.io/ImgSteg/)

一个可恢复原图的纯前端图片隐写工具。无框架、无 CDN、无第三方运行依赖，无需安装或构建。用现代浏览器直接打开 `index.html`；也可以用静态 HTTP 服务打开。所有图片、文字和计算均留在本机。

## 使用

1. 在「制作隐写图片」中选择原图。在图上拖出多个矩形，分别选择马赛克、纯白、纯黑；也可点「添加选区」后精确填写 X/Y/宽/高。坐标以原图像素为单位，矩形右边界、下边界不包含在选区内。支持触摸操作。双击选框或点击列表中的「选中」进入编辑；拖动内部移动，拖动四边或四角缩放，不能越过图片边界或缩小到 1×1 以下。焦点在图片编辑区时，方向键每次微调 1 个原图像素：选中内部时移动整体，选中边/角时仅移动对应的边（上下边忽略左右键，左右边忽略上下键）。Esc 取消选中，可继续画新框。输入框仍保留自身的键盘操作。
2. 可多选上传附加图片，按上传列表顺序存放，支持拖动排序、上移/下移和移除。也可填写附加文字。允许没有选区，只隐写附图或文字。马赛克块大小可调整，重叠区域按列表顺序填充。每个选区保存的始终是原图对应区域的完整 RGBA 像素。
3. 点「计算并生成隐写 PNG」。页面比较压缩方案、列出各分块大小及总长度 n。只有 `n ≤ 9wh` 才写入载荷并提供隐写 PNG 下载；容量不足不会生成不完整图片，但仍可下载底图 i2。
4. 在「识别与还原」中选择隐写 PNG，自动识别并恢复原图、底图 i2、附加图片和文字，可分别下载。附图按存放顺序预览，保留完整原文件字节、文件名与格式（包括元数据和动画），不是重新编码后的图片。识别兼容本项目的 ImgSteg v1/v2，不检测其他工具的隐写格式。

可点「使用合成示例图片」试用；生成后「在本页识别并还原这张图片」会把生成的 PNG 交回同一个读取、识别和提取流程。此过程不依赖网络或本地文件访问扩展。

原有的低位分析功能保留在「仅分析 i2 低位」中，其 n 只包含 i2 的低位压缩分块；「计算并生成」的 n 才包含全部图片恢复数据、文字、文件头与选区记录。剩余比特、字节、等效像素及 1:1 / 4:3 / 16:9 RAW 尺寸始终以当前这次计算的 n 为准。

## 可逆流程

1. 从原图保存选区 RGBA，按选区顺序进行填充，得到 i2。
2. 提取 i2 的 RGB 最低 3 位，按像素 R/G/B、各通道 bit 2 → bit 0 排列（9wh 有效 bit）。比较紧凑打包、RGB 低位值、通道分离、位平面、横向差分和纵向差分，结合可用原生算法选择完整分块体积最小者。
3. 若 i2 非全不透明，另存其 Alpha。各选区依次按完整 RGBA（每通道全部 8 bit）独立压缩，比较逐像素、通道分离、横向/纵向差分和位平面。随后按用户排序逐一保存附图原文件，独立比较全字节压缩候选，不改变文件编码；保存名称、MIME 与尺寸。文字按 UTF-8 编码，独立压缩并放在所有图片数据之后。
4. 加上自描述文件头、选区元数据与 CRC-32，得到最终内容。每块允许原样存储兜底。尝试本机同时支持压缩与解压的 `deflate-raw` / `deflate` / `gzip` / `brotli` / `zstd`，通过运行时探测启用。原生 API 不提供压缩等级控制，不保证超出候选集的理论最优压缩。
5. 检查完整内容长度，按逐像素 RGB、bit 2 → bit 0 写入 i2 的 RGB 低 3 位，未用位补零，高 5 位不变。载体 Alpha 设为 255，导出无损 PNG，避免透明像素预乘造成低位丢失。
6. 恢复时从载体提取内容，恢复 i2 低位和 Alpha，再将所有原始选区贴回 i2 得到原图。分别校验 i2、原图和载荷；生成时从**实际导出的 PNG 文件重新读取**，再次逐字节验证两张图及文字。

### 精度与容量

- PNG IO 是原生 JS + CompressionStream 实现，生成 8 位 RGBA、非交错 PNG，不经过 Canvas 编码。直接读取支持全部 5 种 PNG 行滤波和 8 位非交错 RGB/RGBA；包括 Alpha=0 时的 RGB 也会保留。RGB+tRNS、调色板、灰度、16 位、交错 PNG 等使用浏览器解码。
- 其他输入格式以浏览器 Canvas 解码的 8 位 sRGB 为原图，透明 RGB 可能舍入或被归零。动图仅处理一帧。恢复的是像素，不是输入文件的原始字节；不会保存 EXIF、ICC、动画、16 位精度或原文件编码。直接读取的 PNG 颜色值不进行 ICC 色彩转换。
- 隐写输出为不透明载体；原图和 i2 的 Alpha 在还原时恢复。i2 的白/黑/马赛克填充区域均不透明。马赛克以当前 i2 区域内每个块的 RGB 均值填充，块边界以选区左上角为起点。
- `n = 完整载荷字节数 × 8`，包含容器头、分块头、坐标、校验和、文字及字节补齐。`r = 9wh - n`、`b = r >> 3`、`P = floor(b / 3)` 使用 BigInt 精确计算。负值表示无可用容量。
- 对约分后的宽高比 a:b，`k = floor(sqrt(max(P, 0) / (a*b)))`，最大严格整数尺寸为 `(a*k) × (b*k)`。RAW 以 RGB 每像素 3 字节、无文件头和行补齐计算。
- 最多 4000 万像素、64 个选区，选区累计面积最多 4000 万像素（重叠重复计算）；文字 UTF-8 长度最多 4 MiB，界面限制 100 万 UTF-16 代码单元。实际可用容量以压缩后结果为准，设备内存不足仍可能失败。大图会逐块串行压缩，避免同时运行所有候选。
- 附加图片最多 32 张，原文件总大小最多 32 MiB；每张可解码图像最多 4000 万像素。原文件往往已经压缩，因此候选可能选择原样存储；文件名、类型、尺寸与分块头的长度都计入容量。上传批次先逐张验证，全部成功后按 FileList 顺序追加；失败批次不会添加一半。换载体或取消计算会清空附图列表。
- 解码、填充预览、低位提取、压缩、还原、PNG 输出均在 Blob Worker 中运行。取消或换图会终止 Worker；取消后重新选择图片即可继续。

请保留输出的 PNG 原文件。JPEG 转码、缩放、截图、颜色调整等可能破坏低位。CRC 用于检测损坏，不是密码学认证；本工具没有加密，持有隐写图片的人可以恢复遮盖内容。

## 自描述格式

所有整数均为大端。最终载荷由以下部分连续组成：

```
IMGSTEG1 容器头（无附图时 48 字节），或 IMGSTEG2（有附图时 56 字节）
i2 RGB 低位分块（L3B1）
i2 Alpha 分块（可选，B8C1）
选区 1 记录（24 字节） + 选区 1 RGBA 分块（B8C1）
选区 2 记录 + 选区 2 RGBA 分块
…
附加图片 1 记录 + 原文件字节分块（B8C1）
附加图片 2 记录 + 原文件字节分块
…
UTF-8 附加文字分块（可选，B8C1，始终位于所有图片数据之后）
```

### IMGSTEG1 容器头

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 | 8 | ASCII `IMGSTEG1`（含版本） |
| 8 | 4 | 载荷总字节数，含容器头 |
| 12 | 4 | 图像宽 |
| 16 | 4 | 图像高 |
| 20 | 4 | 选区数 |
| 24 | 4 | L3B1 分块字节数 |
| 28 | 4 | i2 Alpha 分块字节数；0 表示全不透明 |
| 32 | 4 | i2 完整 RGBA 的 CRC-32 |
| 36 | 4 | 原图完整 RGBA 的 CRC-32 |
| 40 | 4 | 容器头之后的全部载荷 CRC-32 |
| 44 | 4 | 末尾文字分块字节数；0 表示无文字 |

选区记录：X/Y/宽/高各 4 字节；填充编号 1 字节（0=马赛克，1=白，2=黑）；保留 3 字节为零；分块字节数 4 字节。记录顺序就是选区顺序，区域数据始终取自原图。恢复 i2 不需要重新执行填充。

### IMGSTEG2 附图扩展

有附加图片时，魔数为 `IMGSTEG2`，容器头共 56 字节。前 48 字节沿用上表的字段含义，偏移 48 增加附图数（uint32），偏移 52 增加附图区段的总字节数（uint32，含所有附图记录和分块）。载荷主体 CRC 从实际头部末尾开始计算，即 v1 从 48、v2 从 56 开始。

附图区段紧接全部原图恢复数据，位于文字之前。每张记录为：UTF-8 文件名字节数（uint16）、MIME 字节数（uint16）、B8C1 字节数（uint32）、图像宽/高（各 uint32），共 16 字节；接着是文件名、MIME 和原文件字节的 B8C1 分块。文件名最多 1024 UTF-8 字节、MIME 最多 128 字节。分块宽=文件字节数、高=1、通道=1。提取时对记录、区段长度、字节总量和分块 CRC 校验，并按记录顺序返回原文件。无附图仍输出 v1，当前解码器兼容两版；旧版页面不能读取新的 v2 载荷。

### L3B1 低位分块（兼容旧版 `.lsb3`）

20 字节头：`L3B1` 4 字节；排列编号 1 字节（0=紧凑打包，1=RGB 值，2=通道分离，3=位平面，4=左差分，5=上差分）；算法编号 1 字节；保留 2 字节；宽、高各 4 字节；规范紧凑打包数据（含零补齐）的 CRC-32 4 字节。余下为编码内容。

规范紧凑打包顺序是逐像素 R/G/B，每值 bit 2/1/0，末字节低位补零。位平面按 R/G/B 通道、bit 2/1/0、逐行像素连续打包，平面间不补齐。差分以同通道左邻或上邻为预测值，边界预测 0，模 8 运算。

### B8C1 全比特分块

20 字节头：`B8C1` 4 字节；宽、高各 4 字节；通道数 1 字节（1、3 或 4）；排列编号 1 字节（0=逐像素，1=通道分离，2=左差分，3=上差分，4=位平面）；算法编号 1 字节；保留 1 字节；原始字节 CRC-32 4 字节。余下为编码内容。

差分模 256 运算，边界预测为 0。位平面按通道、bit 7 → 0、逐行像素连续打包。文字使用宽=UTF-8 字节数、高=1、通道=1；保留开头 BOM、换行、NUL、中文和 emoji，不作 HTML 解析。

算法编号通用于两种分块：0=raw，1=deflate-raw，2=deflate，3=gzip，4=brotli，5=zstd。raw 只允许排列 0。新算法在浏览器支持时才启用；解码端也须支持分块记录的算法。原生接口参考：[Compression Standard](https://compression.spec.whatwg.org/)。

## 文件与开发验证

- `index.html` / `style.css` / `app.js`：页面、选区交互、Worker 调度及导出。
- `codec.js`：RGB 低位编解码、精确容量与 RAW 尺寸计算。
- `steg.js`：RGBA 全比特分块、容器、位写入与还原。
- `png.js`：无损 PNG 编解码，避免载荷经过 Canvas 预乘。
- `editor.js`：选框命中、移动、八方向缩放及 1 像素键盘微调的几何逻辑。

发布仓库通过 `.gitignore` 排除 `test/`、`tests/` 以及任意层级名称以 `.` 开头的目录，并明确允许 `.github/`，以便将 GitHub 配置纳入版本控制。测试、生成样例和截图保留在本地开发副本，不随仓库或 Pages 发布。以下测试命令仅适用于保留本地 `tests/` 目录的开发副本，需要 Node.js 22+，无 npm 依赖（运行网页不需要 Node）：

```sh
node --test tests/*.test.cjs
node tests/make-fixtures.cjs
```

测试覆盖全排列/原生算法独立解码、重叠选区与填充顺序、透明 RGBA、PNG 导出再读取、中文/emoji/BOM/NUL、文字尾部顺序、零选区、容量超限和恰好装满、错误元数据、损坏载荷/高位、独立生成的 PNG 五种滤波，以及解压长度上限。合成样例输出到 `tests/fixtures/`，可手动用于上传测试。

另覆盖八方向编辑、边缘方向键限制、最小尺寸和越界保护、附图顺序与原文件逐字节还原、元数据开销、v1/v2 兼容及错误区段拒绝。可通过本机静态服务器打开 `tests/browser.html`，其测试按钮会在浏览器内生成两张小 PNG，通过真实文件 input 的 change 处理器上传，不读取本地文件或绕过扩展权限。

## GitHub Pages 部署

本项目通过 `main` 分支根目录发布到 [GitHub Pages](https://richadowonosas.github.io/ImgSteg/)。根目录的 `.nojekyll` 让 Pages 直接提供静态文件。无需构建、npm 安装或 `.github/workflows`，页面只使用浏览器原生 API。
