# ImgSteg（图隐）

[English](README.md) · [在线使用](https://richadowonosas.github.io/ImgSteg/)

一个可恢复原图的纯前端图片隐写工具。无框架、无 CDN、内置固定版本 JS/WASM 编解码库，无需安装或构建。用现代浏览器直接打开 `index.html`；也可以用静态 HTTP 服务打开。所有图片、文字和计算均留在本机。

遮盖隐写与差分图隐写可以同时使用。底部悬浮栏默认以完整字节数（byte）显示剩余容量，精确的剩余比特数（bit）放在展开详情中；完整载荷占用和进度常显，其余结果点击展开；模式导航吸顶。主题设置提供亮色、暗色、跟随系统及 0–360° 色相，默认 270°，偏好仅保存在当前浏览器本机。

## 使用

基底图片的拖放上传仅限左侧「图片预览」面板，已有图片时会询问追加为差分图，还是更换为一批新图片。其他区域拖入文件不会上传或换图，只会阻止浏览器直接打开文件；附图列表内部排序不受影响。

差分图列表中点击缩略图、标题或行内空白即可切换预览；可编辑选区行点击标题或非控件空白即可选中。下拉框、坐标输入、关联标签及功能按钮继续独立操作，不会额外触发整行切换；原有预览/选中按钮仍保留，自动框和全图 XOR 的选区仍只读。

1. 在「制作隐写图片」中选择原图。在图上拖出多个矩形，分别选择马赛克、纯白、纯黑；也可点「添加选区」后精确填写 X/Y/宽/高。坐标以原图像素为单位，矩形右边界、下边界不包含在选区内。支持触摸操作。双击选框或点击列表中的「选中」进入编辑；拖动内部移动，拖动四边或四角缩放，不能越过图片边界或缩小到 1×1 以下。焦点在图片编辑区时，方向键每次微调 1 个原图像素：选中内部时移动整体，选中边/角时仅移动对应的边（上下边忽略左右键，左右边忽略上下键）。Esc 取消选中，可继续画新框。输入框仍保留自身的键盘操作。
2. 可多选上传附加图片，按上传列表顺序存放，支持拖动排序、上移/下移和移除。也可填写附加文字。允许没有选区，只隐写附图或文字。马赛克块大小可调整，重叠区域按列表顺序填充。每个选区保存的始终是原图对应区域的完整 RGBA 像素。
3. 点「计算并生成隐写 PNG」。页面比较压缩方案、列出各分块大小及总长度 n。只有 `n ≤ 9wh` 才写入载荷并提供隐写 PNG 下载；容量不足不会生成不完整图片，但仍可下载底图 i2。
4. 在「识别与还原」中选择隐写 PNG，自动识别并恢复原图、底图 i2、差分图、附加图片和文字，可分别下载。附图按存放顺序预览，保留完整原文件字节、文件名与格式（包括元数据和动画），不是重新编码后的图片。识别兼容本项目的 ImgSteg v1/v2/v3/v4/v5/v6/v7/v8，不检测其他工具的隐写格式。底部「容量与结果」可展开查看全部预览和下载入口，生成后的快速 PNG 下载常显。

## 差分图

可以一次上传/拖入多张图片，选择一张作为基底，其余按上传顺序成为同尺寸差分图。基底也显示在「差分图与父本」中：「原图预览」显示未遮盖原图，「遮盖预览」显示遮盖后的 i2，「编辑遮盖」编辑其遮盖选区。遮盖后的 i2 是不可被选择的隐式根；未遮盖基底从 i2 恢复，差分图可选这张未遮盖基底或其他差分图作为父本，包括后上传的图片。所有路径必须最终到达基底，自引用、缺失父本和循环均会拒绝。删除父本时，其直接子图改接基底，并使旧覆盖信息失效。

已有基底时，在「图片预览」区域拖入一批图片会询问「作为差分图添加」或「更换为一批新图片」。显式「更换基底图」始终进入替换流程；替换或左侧「清空」会清除旧差分图、遮盖、附图与缓存。差分图的「预览」及行非控件点击显示原色，不显示差异蒙层和选框；「编辑」进入差异框选。生成按钮右侧下拉菜单提供「仅分析 i2 低位」。

逐像素比较 RGBA 全部字节，包括 Alpha 变化；每张提供四种方式：

- **自动框选**：最大数量可设 1–256（默认 20），完整覆盖所有差异像素。
- **32×32 分块自动**：按分块收缩并合并，只读预览，行列默认各 32、可分别设置，乘积不超过 65536，最多 65536 个结果矩形。
- **手动框选**：预览压暗 50%，差异像素显示白色 `#FFFFFF`。添加第一个框后，仍未覆盖的差异显示浅红 `#FFDDDD`。可继续添加、移动、缩放或精确编辑坐标；未覆盖完整时拒绝打包，每张最多 64 框。
- **全图差值**：直接将整张图与父本的 RGBA 做异或，再压缩整个结果，不需要框选。差异稀疏时，全图中的大量零值同样可能压缩得很好。

自动框选参考 [OpenCV 连通分量与边界框方法](https://docs.opencv.org/4.5.4/d3/dc0/group__imgproc__shape.html)，但实现不依赖 OpenCV。差异掩码先投到最多 256×256 的自适应网格，每格保存真实变化像素的紧边界；在格网上计算 8 连通分量。分量过多时按 Morton 空间顺序分组，再按「合并后矩形的新增覆盖面积最小」逐对贪心合并，直到形成不超过 10 个初始框。随后计算并缓存每个框按行、列拆分的最大像素面积收益，每轮从全部框中选择收益最大的一刀；收益相同时优先沿空白行/列断开。直到达到设定上限或全部无正收益。算法保证覆盖与有界内存/合并耗时，不保证矩形面积或压缩率的全局最优。

每个框保存父本与子图的 RGBA XOR，全字节分块独立择优压缩。恢复每个框时始终以未修改的父本为基准，因此重叠框不会互相抵消。全部图按无环拓扑顺序恢复并逐张校验；存储与输出仍保留上传顺序。差分图最多 16 张，合计最多 4000 万像素。恢复的是解码后的像素 PNG，不保存这些差分图原文件的编码、动画和元数据；如需保留原文件，请使用附加图片。

## 计算缓存

页面保留最近一次完整生成及最近一次低位分析的结果。载体、框选坐标/填充、马赛克大小、差分父本/方式/手动框、附图顺序和文字相同，直接复用保存的容量和输出 Blob。仅选中框、切换预览或更改主题不触发压缩。

内容变化时仍可复用 Worker 内未改变的 i2 低位/Alpha、原图区域、附图原文件及 XOR 分块；例如只改文字不必重压 i2。压缩缓存有数量和字节限制，换载体或取消会清空，不写入磁盘。真正影响载荷的变化都会使相应结果失效。

可点「使用合成示例图片」试用；生成后「在本页识别并还原这张图片」会把生成的 PNG 交回同一个读取、识别和提取流程。此过程不依赖网络或本地文件访问扩展。

原有的低位分析功能保留在「仅分析 i2 低位」中，其 n 只包含 i2 的低位压缩分块；「计算并生成」的 n 才包含全部图片恢复数据、文字、文件头与选区记录。剩余比特、字节、等效像素及 1:1 / 4:3 / 16:9 RAW 尺寸始终以当前这次计算的 n 为准。

## 可逆流程

1. 从原图保存选区 RGBA，按选区顺序进行填充，得到 i2。
2. 提取 i2 的 RGB 最低 3 位，按像素 R/G/B、各通道 bit 2 → bit 0 排列（9wh 有效 bit）。比较紧凑打包、RGB 低位值、通道分离、位平面、横向差分和纵向差分，结合可用原生算法选择完整分块体积最小者。
3. 若 i2 非全不透明，另存其 Alpha。各选区依次按完整 RGBA（每通道全部 8 bit）独立压缩，比较逐像素、通道分离、横向/纵向差分和位平面。随后按用户排序逐一保存附图原文件，独立比较全字节压缩候选，不改变文件编码；保存名称、MIME 与尺寸。文字按 UTF-8 编码，独立压缩并放在所有图片数据之后。
4. 加上自描述文件头、选区元数据与 CRC-32，得到最终内容。每块允许原样存储兜底。尝试本机同时支持压缩与解压的 `deflate-raw` / `deflate` / `gzip` / `brotli` / `zstd`，通过运行时探测启用。原生 API 不提供压缩等级控制，不保证超出候选集的理论最优压缩。
5. 检查完整内容长度，按逐像素 RGB、bit 2 → bit 0 写入 i2 的 RGB 低 3 位，未用位补零，高 5 位不变。载体 Alpha 设为 255，导出无损 PNG，避免透明像素预乘造成低位丢失。
6. 恢复时从载体提取内容，恢复 i2 低位和 Alpha，再将所有原始选区贴回 i2 得到原图。分别校验 i2、原图和载荷；生成时从**实际导出的 PNG 文件重新读取**，再次逐字节验证两张图及文字。

### 精度与容量

- PNG IO 是原生 JS + CompressionStream 实现，生成 8 位 RGBA、非交错 PNG，不经过 Canvas 编码。直接读取支持全部 5 种 PNG 行滤波和 8 位非交错 RGB/RGBA；包括 Alpha=0 时的 RGB 也会保留。RGB+tRNS、调色板、灰度、16 位、交错 PNG 等使用浏览器解码。
- 其他输入格式以浏览器 Canvas 解码的 8 位 sRGB 为原图，透明 RGB 可能舍入或被归零。动图仅处理一帧。恢复的是像素，不是输入文件的原始字节；不会保存 EXIF、ICC、动画、16 位精度或原文件编码。直接读取的 PNG 颜色值不进行 ICC 色彩转换。
- 隐写输出为不透明载体；原图和 i2 的 Alpha 在还原时恢复。i2 的白/黑/马赛克填充区域均不透明。马赛克以当前 i2 区域内每个块的 RGB 均值填充，块边界以选区左上角为起点。
- `n = 完整载荷字节数 × 8`，包含容器头、分块头、坐标、校验和、文字及字节补齐。`r = 9wh - n`、`b = r >> 3`、`P = floor(b / 3)` 使用 BigInt 精确计算。负值表示无可用容量。
- 对约分后的宽高比 a:b，`k = floor(sqrt(max(P, 0) / (a*b)))`，最大严格整数尺寸为 `(a*k) × (b*k)`。RAW 以 RGB 每像素 3 字节、无文件头和行补齐计算。
- 最多 4000 万像素、64 个选区，选区累计面积最多 4000 万像素（重叠重复计算）；文字 UTF-8 长度最多 4 MiB，界面限制 100 万 UTF-16 代码单元。实际可用容量以压缩后结果为准，设备内存不足仍可能失败。大图会逐块串行压缩，避免同时运行所有候选。
- 附加图片最多 32 张，原文件总大小最多 32 MiB；每张可解码图像最多 4000 万像素。原文件往往已经压缩，因此候选可能选择原样存储；文件名、类型、尺寸与分块头的长度都计入容量。上传批次先逐张验证，全部成功后按 FileList 顺序追加；失败批次不会添加一半。换载体或取消计算会清空附图列表。
- 解码、填充预览、低位提取、压缩、还原、PNG 输出均在 Blob Worker 中运行。取消或换图会终止 Worker；取消后重新选择图片即可继续。

请保留输出的 PNG 原文件。JPEG 转码、缩放、截图、颜色调整等可能破坏低位。CRC 用于检测损坏，不是密码学认证；本工具没有加密，持有隐写图片的人可以恢复遮盖内容。

## 自描述格式

所有整数均为大端。最终载荷由以下部分连续组成：

```
IMGSTEG1（48 字节）、IMGSTEG2（56 字节）或 IMGSTEG3–6（64 字节）容器头
i2 RGB 低位分块（L3B1）
i2 Alpha 分块（可选，B8C1）
选区 1 记录（24 字节） + 选区 1 RGBA 分块（B8C1）
选区 2 记录 + 选区 2 RGBA 分块
…
差分图区段（可选，DIF1，含父本图结构与各图的 XOR 分块）
附加图片 1 记录 + 原文件字节分块（B8C1）
附加图片 2 记录 + 原文件字节分块
…
UTF-8 附加文字分块（可选，B8C1，始终位于所有图片数据之后）
```

### IMGSTEG1 容器头

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 | 8 | ASCII `IMGSTEG1`（含版本） |
| 8 | 4 | 载荷总字节数，含容器头 |
| 12 | 4 | 图像宽 |
| 16 | 4 | 图像高 |
| 20 | 4 | 选区数 |
| 24 | 4 | L3B1 分块字节数 |
| 28 | 4 | i2 Alpha 分块字节数；0 表示全不透明 |
| 32 | 4 | i2 完整 RGBA 的 CRC-32 |
| 36 | 4 | 原图完整 RGBA 的 CRC-32 |
| 40 | 4 | 容器头之后的全部载荷 CRC-32 |
| 44 | 4 | 末尾文字分块字节数；0 表示无文字 |

选区记录：X/Y/宽/高各 4 字节；填充编号 1 字节（0=马赛克，1=白，2=黑）；保留 3 字节为零；分块字节数 4 字节。记录顺序就是选区顺序，区域数据始终取自原图。恢复 i2 不需要重新执行填充。

### IMGSTEG2 附图扩展

有附加图片时，魔数为 `IMGSTEG2`，容器头共 56 字节。前 48 字节沿用上表的字段含义，偏移 48 增加附图数（uint32），偏移 52 增加附图区段的总字节数（uint32，含所有附图记录和分块）。载荷主体 CRC 从实际头部末尾开始计算，即 v1 从 48、v2 从 56 开始。

附图区段紧接全部原图恢复数据，位于文字之前。每张记录为：UTF-8 文件名字节数（uint16）、MIME 字节数（uint16）、B8C1 字节数（uint32）、图像宽/高（各 uint32），共 16 字节；接着是文件名、MIME 和原文件字节的 B8C1 分块。文件名最多 1024 UTF-8 字节、MIME 最多 128 字节。分块宽=文件字节数、高=1、通道=1。提取时对记录、区段长度、字节总量和分块 CRC 校验，并按记录顺序返回原文件。无附图仍输出 v1，当前解码器兼容两版；旧版页面不能读取新的 v2 载荷。

### L3B1 低位分块（兼容旧版 `.lsb3`）

20 字节头：`L3B1` 4 字节；排列编号 1 字节（0=紧凑打包，1=RGB 值，2=通道分离，3=位平面，4=左差分，5=上差分）；算法编号 1 字节；保留 2 字节；宽、高各 4 字节；规范紧凑打包数据（含零补齐）的 CRC-32 4 字节。余下为编码内容。

规范紧凑打包顺序是逐像素 R/G/B，每值 bit 2/1/0，末字节低位补零。位平面按 R/G/B 通道、bit 2/1/0、逐行像素连续打包，平面间不补齐。差分以同通道左邻或上邻为预测值，边界预测 0，模 8 运算。

### B8C1 全比特分块

20 字节头：`B8C1` 4 字节；宽、高各 4 字节；通道数 1 字节（1、3 或 4）；排列编号 1 字节（0=逐像素，1=通道分离，2=左差分，3=上差分，4=位平面）；算法编号 1 字节；保留 1 字节；原始字节 CRC-32 4 字节。余下为编码内容。

差分模 256 运算，边界预测为 0。位平面按通道、bit 7 → 0、逐行像素连续打包。文字使用宽=UTF-8 字节数、高=1、通道=1；保留开头 BOM、换行、NUL、中文和 emoji，不作 HTML 解析。

算法编号通用于两种分块：0=raw，1=deflate-raw，2=deflate，3=gzip，4=brotli，5=zstd。raw 只允许排列 0。新算法在浏览器支持时才启用；解码端也须支持分块记录的算法。原生接口参考：[Compression Standard](https://compression.spec.whatwg.org/)。

### IMGSTEG3/4 与 DIF1 差分扩展

有差分图且无遮盖时使用 `IMGSTEG3`；同时包含遮盖时使用 `IMGSTEG4`，容器头共 64 字节；前 56 字节沿用 v2（无附图时相应两个字段置零）。偏移 56 为差分图数 uint32，60 为 DIF1 区段长度 uint32。主体 CRC 从实际头部末尾开始计算。差分区段位于原图恢复数据之后、普通附图与文字之前；无差分图的情况下仍按有无附图输出 v2/v1。

DIF1 开头 20 字节依次为 `DIF1`、图数、宽、高、根图 RGBA CRC-32（v3 为 i2，v4 为恢复后的未遮盖原图），后四项均 uint32。每张图记录 16 字节：文件名 UTF-8 长度 uint16、框数 uint16、父本索引 uint32（0=基底，其他为上传顺序的 1 起始索引）、子图 RGBA CRC-32 uint32、保留零 uint32，然后是文件名字节。每框为 X/Y/宽/高/B8C1 长度五个 uint32，再接完整 RGBA XOR 的 B8C1 分块。自动模式下相同图片可以零框；全图 XOR 为一个全尺寸框。解析会验证尺寸、计数、长度、父本路径、循环和每张恢复图的 CRC。

## 文件与开发验证

- `index.html` / `style.css` / `app.js`：页面、选区交互、Worker 调度及导出。
- `codec.js`：RGB 低位编解码、精确容量与 RAW 尺寸计算。
- `steg.js`：RGBA 全比特分块、容器、位写入与还原。
- `png.js`：无损 PNG 编解码，避免载荷经过 Canvas 预乘。

## 稀疏差分与本地高压缩编解码库

每个差分框比较「完整 RGBA XOR」与「每像素 1 bit 变化掩码＋变化像素完整 RGBA XOR」。掩码和值一起压缩，计入额外头部后更小时才选择稀疏方案；稠密或无变化数据可继续选择整框方案，重叠框仍对未改动父本恢复。容量详情显示所选方法和相对整框节省的字节数。

除原生算法外，新增 **fflate 0.8.2 的 DEFLATE level 9** 与 **brotli-wasm 3.0.1 的 Brotli quality 5**，参与低位及全字节预处理组合择优。转换后的单份输入超过 8 MiB 时跳过Brotli-5/LZMA2 WASM 试压，保留其他候选。WASM 初始化失败时跳过该候选。代码及 WASM 随仓库内置，WASM 字节嵌入经典脚本后放入原有 Worker，不需要 CDN、后端、npm 安装或打包。许可证、固定版本、来源及可复现构建方式见 [vendor/README.md](vendor/README.md)。

L3B1/B8C1 算法编号新增 6=本地 DEFLATE-9、7=本地 Brotli-5（兼容旧 Q11）；0–5 不变。底层仍为标准 raw DEFLATE/Brotli 比特流。原生 Brotli/raw DEFLATE 解码不可用时可回退内置库。旧读取端可能无法读取使用新算法编号的内容，即使其外层仍为 v1–v4。

非分块模式使用稀疏块时输出 **IMGSTEG5**（64 字节头及根图含义沿用 v4）和 **DIF2**。仅整框块仍可输出 DIF1/v3/v4。DIF2 记录结构与 DIF1 相同，每框可以保存原 B8C1 或 SPX1。SPX1 的 20 字节头为 magic、宽、高、变化像素数、完整 XOR 的 CRC-32，四项数值均大端 uint32，后接一个 B8C1。解码后为 `ceil(w*h/8)` 字节的高位优先掩码、`4*count` 字节 RGBA XOR 值及补齐四字节的全零填充，按宽=补齐长度/4、高=1、通道=4 编码。验证数量、尺寸、掩码尾位、填充、非零变化值及 CRC。当前读取兼容 v1–v8、DIF1/DIF2/DIF3/DIF4；新格式需用新版工具还原。

局部合成样例实测：浏览器 128×128 结构化低位数据由原生方案 235 byte 减至 Brotli WASM 的 77 byte，全候选比较约 87 ms→514 ms；256×256 稀疏随机变化 XOR 分块含头部由 4,674 byte 减至 4,113 byte（约 12%）。稠密随机及全零样例继续选整框。以上不是通用收益承诺，高质量试压会增加时间及工具本身的下载体积。本次验证新 v5 PNG 完整恢复和旧 v1–v4 兼容，未跑全量回归。

## 32×32 分块自动与普通自动细分

差分图编码方式新增「32×32 分块自动」，点击「分块预览」查看结果。长宽各分为 32 个整数区间，边界按 `floor(i*尺寸/32)` 计算，不整除时仍覆盖全部像素；尺寸不足 32 时按像素数分成非空区间。有变化的块收缩到精确差异边界，无变化块丢弃。只有完全未收缩的块参与合并，不跨空块或收缩块。

合并比较横向扫描、纵向扫描，以及两种同面积优先次序的最大矩形贪心划分，最后继续合并有完整共同边的相邻矩形，取框数更少的方案（同数比较周长）。保证每个可合并格恰好覆盖一次，不保证全局最少矩形或最小压缩体积。

灰色网格显示原始分块；橙框为收缩、绿框为合并、紫框为未收缩单块。图例改为纵向，并分别显示原始分块总数、收缩结果框数、合并结果框数、未收缩单块数。统计显示变化块、收缩块和合并减少量。此模式只读，不显示手动画框/调整按钮、控制点或大量坐标输入列表；原色预览仍保留。底部容量详情统一按图片使用默认收起的二级折叠，所有编码方式都适用。基底原图组包括 i2 低位、可选 Alpha 和全部遮盖选区恢复数据；每张差分图单独一组，零变化图片也保留记录。摘要显示选框数及含对应图片/选框记录的总字节数；展开后显示逐框算法和字节，超过 200 条明细分页并延迟绘制。附图、文字和共用容器开销单列。生成按钮及侧边低位分析菜单放在底部悬浮栏，识别还原模式隐藏生成控件。预览和打包共用矩形计算，每框继续择优整框/稀疏 XOR 及本地编解码库。碎块多时头部和试压次数也会增加，可与普通自动模式比较实际容量。

请求网格不超过 1024 格的分块模式输出 **IMGSTEG6 / DIF3**：64 字节头、差分根语义沿用 v4/v5，DIF3 的记录和稠密/SPX1 分块结构不变，但每图最多允许 1024 个分块；旧 DIF1/DIF2 解析仍限 64。手动上限仍为 64，普通自动默认 20、可设至 256；普通自动转手动保留细分后的框。分块文件需新版工具读取，旧版 v1–v5 仍可还原。

本次局部测试覆盖小掩码最优切割穷举对照、大框无收益时继续小框、空白带断开、20 框上限、分块精确收缩/合并、微小及不整除尺寸、1024 个收缩框与稀疏 DIF3 编解码、组合遮盖的 v6 PNG 恢复。浏览器验收确认只读预览、99 个变化块得到 4 个结果矩形、带附图/文字完整还原，以及普通自动 20 框转手动坐标逐项保留。未跑全量回归。

## LZMA2 与 Brotli 提速

当前版本内置固定的 `lzma-wasm` 1.0.7，增加 **LZMA2（CRC64 XZ，preset 3）**，算法编号 **8**。Brotli 默认等级由 **11 降为 5**；编号 **7** 仍表示标准 Brotli 流，旧质量 11 文件无需改变即可读取。压缩算法编号不改变外层容器选择，含编号 8 的载荷需新版工具还原。两个库均本地内置，计算仍在 Worker，无 CDN 或后端。转换输入超过 8 MiB 时跳过这两种 WASM 试压；现有最小分块已小于等于 XZ 最小开销时也跳过无收益试压。

局部验证包括 Python 标准 XZ 双向互通、XZ 截断/尾部/损坏/伪造长度、字典与输出限制、旧 Brotli-11、候选择优、WASM 不可用回退，以及浏览器含透明像素隐藏 RGB 的 PNG 生成还原。同一份已预热的 128×128 合成低位样例，旧 Q11 全候选为 553 ms／77 byte，新 Q5＋LZMA2 为 84 ms／96 byte；仅代表该样例的速度与体积取舍。另一浏览器样例的完整 RGBA 选区择优采用 LZMA2，分块为 7040 byte，并成功独立还原。

## 自动选择参数与 v7 格式

选区栏顶部可设置普通自动的最大数量（1–256，默认 20），或分块行数与列数（各 1–65536，乘积不超过 65536，默认 32×32）。点击「应用参数」生效；无效输入保留已应用结果，参数未变则复用缓存。设置随差分边保存，重新指定基底时一起迁移，预览与打包使用同一计划。普通自动转手动保留当前框；结果超过手动 64 框上限时需先降低自动上限，避免丢框。

普通自动上限大于 64 或请求分块总数大于 1024 时输出 **IMGSTEG7 / DIF4**，其他配置沿用已有版本选择。外层仍为 64 字节头、以恢复后的未遮盖原图作为差分根。DIF4 区段头仍 20 字节；每图头改为 20 字节：uint16 文件名长度、uint16 策略标记（0=手动/全图、1=分块、2=普通自动）、uint32 框数量、uint32 父本索引、uint32 RGBA CRC-32、uint32 保留零，随后为文件名。每框记录和 B8C1/SPX1 不变，三类数量上限分别为 64/65536/256；分块框累计面积不得超过整图。所有整数大端，不需要网格信息或外部字典即可恢复。旧版读取端无法读取 v7。

大网格/大量结果框由 Worker 栅格化预览，不创建数万个 SVG/表单节点。合并搜索设置工作量上限，保留精确覆盖的扫描方案；相同小块复用压缩结果，过长算法明细汇总展示。局部验证覆盖恰好 65536 框往返、256 自动框、无效值、参数缓存、重定根和 v7 PNG 恢复；浏览器验证自定义参数、无效输入保留结果、导出 PNG 校验及 65536 框预览。未跑全量回归。


## i2 稀疏编码与循环减法（v8）

无需新增开关，直接在候选中择优：i2 RGB 低位新增每通道众数默认值＋例外，以及横向、纵向模 8 预测残差的稀疏表示。预测只依赖已恢复的相邻低位，行/列边界预测为零，不依赖尚未恢复的原图。例外表示未压缩长度不小于紧凑 RGB 打包时跳过，否则与现有全部布局和压缩算法比较，保留原样存储候选。

L3B1 新布局 **6/7/8** 分别对应默认值稀疏、横向残差稀疏、纵向残差稀疏。内部数据依次为三个通道默认值字节、一个保留零字节、大端 uint32 例外数量、覆盖 `3wh` 个通道样本的高位优先掩码、每例外 3bit 紧凑数值。残差默认值必须为零；解码验证限长、默认值、数量、精确长度、掩码/数值尾位、例外非默认值及原低位 CRC。

Alpha 单独增加默认 255＋像素掩码＋8bit 例外候选，整幅 Alpha 压缩仍参与比较。**ALP1** 的 20 字节头为 magic、宽、高、例外数量、恢复 Alpha 的 CRC-32（四项数值大端 uint32），后接 B8C1（宽=掩码及例外总字节数、高1、通道1）。完全不透明时仍不保存 Alpha。

每个差分选区同时比较 **XOR** 与 **`(子图−父本) mod 256`**，RGBA 四通道都参与，各自再比较整框和 SPX1 稀疏表示。两种运算共用差异掩码及选框。循环减法只有在包含额外 **SUB1** 四字节标记后仍更小时才被采用，标记之后为现有 B8C1 或 SPX1；恢复时对未修改父本模 256 相加，因此重叠框也正确。XOR 分块和掩码继续对称缓存，减法最终结果按父子方向缓存，换根后不会误用反向结果。详情以 XOR 或 SUB 显示实际运算。

采用任一新增低位稀疏、Alpha 稀疏或 SUB1 分块时输出 **IMGSTEG8**，外层 64 字节头、未遮盖原图根语义不变。v8 允许没有差分图，此时差分数量和区段长度同时为零；DIF1–DIF4 记录结构不变，SUB1 仅允许在 v8 中使用。低位与 Alpha 的节省量还要联合抵扣外层头部增加量，无实际收益则保留旧块及旧版本选择。新版兼容读取 v1–v8，旧工具无法读取新增分块；不需要外部字典。

局部验证覆盖三种稀疏布局、预测残差实际择优、稠密回退、损坏拒绝、正反方向模运算、重叠框、位翻转时保留 XOR、纯低位/纯 Alpha 的 v8、带遮盖及前向父本/附图/文字的 PNG 完整恢复和相关旧格式。浏览器验证低位/Alpha 稀疏、减法选中、换基底后反向减法及独立载入 v8 还原。额外试压可能增加处理时间，压缩收益取决于素材；无需新增运行时依赖。


计算并生成或仅分析低位期间，仍可点击差分行、原色预览、编辑/分块预览，以及查看基底原图和遮盖预览。父本、编码、选框及其他影响载荷的编辑继续锁定；切换预览不重新计算、不改变当前生成的配置快照。预览回复按当前选择过滤，既不会解除生成锁，也不会覆盖生成进度。读取图片、切换基底等其他任务沿用原锁定规则。
